cancho-fetch · alpha prerelease

An HTTP client whose hosts are in the binary.

Give an agent curl and it can reach any host, with any header, and follow any redirect. fetch can dial only the hosts its builder wrote into it, and says so in its authority row, where a reviewer can read it without running anything.

One binary, two readers

  
A person reads the host list. An agent reads a refusal and fixes the call.

  

    
    
  


  

    

      
Read the list, not the code
fetch introspect prints one net_out label per host. The same list is what the run-time check compares against. The label is: {"name":"net_out","argument":"127.0.0.1:18090","bounded":true}

      
Secrets stay in files
A credential is a path given at build time (--credential HOST=PATH), read when needed and sent only to that host. It is never an argument, so it is never in a transcript.

      
Bounded
A body cap, a timeout, no redirects unless asked, and a refusal to dial a private address unless the builder allowed it. Each is a refusal with a rule, not a hang.

Prompt for your agent
Try cancho-fetch against a server on this machine and tell me what you see. Work in a new empty directory, never use sudo, and report honestly: do not retry a failing command in a loop and do not hide a failure.

1. Check that git, python3, cargo (Rust) and clang exist. If one is missing, stop and tell me which; do not install system packages yourself.
2. Get the sources and the compiler they pin:
   git clone https://github.com/alpibrusl/cancho
   git clone https://github.com/alpibrusl/cancho-fetch && cd cancho-fetch
   REV=$(sed -n 's/^cancho *= *"\([0-9a-f]*\)".*/\1/p' cancho.toml)
   (cd ../cancho && git fetch -q origin && git checkout "$REV" && cargo build --release -p cancho)
   export PATH=$PWD/../cancho/target/release:$PATH
3. In another shell, serve a directory with one file, items.json, on 127.0.0.1:18090:
   mkdir -p /tmp/api && echo '{"items":[1,2]}' > /tmp/api/items.json && python3 -m http.server 18090 --bind 127.0.0.1 --directory /tmp/api
4. Build a fetch for that one host (about three minutes: most of it is compiling the TLS packages):
   python3 scripts/fetch_build.py --host http://127.0.0.1:18090 --allow-private
5. Run, and note the exit status and `rule` (or `data.status`) of each:
   build/fetch get /items.json --host 127.0.0.1:18090            # expect status 200
   build/fetch get /items.json --host 127.0.0.1:18099            # expect fetch.host-not-allowed, exit 2
   build/fetch introspect | jq -c '.authority.labels[] | select(.name == "net_out")'   # the only host in the row
6. Tell me the three results, what the build printed if it failed, and anything that surprised you.
Docs: README.md, docs/design.md.

    

  






  
What alpha means here

  
It is built and tested. It is not ready to be the only thing between an agent and the network.

  

    
Built and tested
  • get, head and post over http and https
  • baked hosts, one net_out label each
  • body cap, timeout, redirects off by default and only ever to baked hosts
  • refusal to dial private addresses unless allowed
  • credentials from files, sent to their own host only
  • CLI, introspect, skill, MCP

    
Not built yet
  • wildcard hosts for https
  • several credentials for one host
  • a shared MCP module with the sibling tools
  • ALPN and session resumption

    
Not planned
  • ssh and other HTTP methods
  • proxies and cookies
  • HTTP/2 and client certificates

  

  

    
TLS, said plainly

    
https runs on cancho's own TLS client, written in cancho. It has not had an independent security review (tracked in cancho issues #209 and #281). A handshake costs several times the CPU of OpenSSL's.

    
The trust roots are a PEM bundle the builder passes with --roots; they are embedded at build time. No flag turns certificate verification off.

    
Until that review exists, treat https here as unreviewed, and prefer http on a trusted network or a reviewed proxy for anything that matters.

  






  
Measured, not promised

  
One process per request, medians, against curl 8.5.0 with OpenSSL 3.0.13 (design.md §8.7). Small requests are faster; a 16 MB body is not.
