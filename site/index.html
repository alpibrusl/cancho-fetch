Design only. Nothing is built.

HTTP to a list of hosts you can read.

An agent-safe fetch written in cancho. The hosts it may reach are a literal in the binary, shown by cancho authority as one net_out label each. Nothing else in the binary can reach the network.

Read the design Repository cancho-tools

The idea

The list is in the row

A reviewer reads net_out("api.example.com:443") instead of trusting a flag a caller can set.

One binary per list

A different allow-list is a different build. A host removed shrinks the row; a host added changes the build input.

Refusals are data

A host outside the list, a redirect elsewhere, a body over the cap: each is a rule tag with a repair, not a sentence on stderr.

fetch get  /v1/items --host api.example.com --max-bytes 65536
fetch post /v1/items --host api.example.com --body-stdin

The authority row

For a build with two hosts, the design expects this (to be measured at step 1):

performs
    io_write
    net_out("api.example.com:443")
    net_out("static.example.com:443")
    fs_read("/dev/urandom")       the TLS seed
    fs_read("<roots bundle>")    the trust anchors
    clock                         the deadline
bounded: true    ffi: none    net_in: none

This depends on cancho's exact host matching (edition 10, cancho#561). Before it, the host half of a bound is a prefix: 127.0.0.1 admits 127.0.0.10.

What it will not do

Not offeredWhy
A full URL, or a host outside the listA URL is a second place a host can be written. Refused before a socket opens.
Authorization, Cookie, proxiesNo credentials in v1; an open question in the design.
Methods other than GET, HEAD, POSTThe rest of curl is a refusal with a pointer to curl.
Guarantees about the resolved addresscancho checks the name, not the address. A non-public peer is refused after connect, which stops the request but not the handshake. The design says so.
sshNo design, no asker, and "what may the agent do on the other side" has no answer a row can show.

Plan

  1. cancho#561 merged; scaffolding and the ceiling gate.
  2. Plain HTTP GET and HEAD to a baked host on loopback; measure the row, the peer check and the resolver caveat.
  3. HTTPS, with the trust roots and the seed. The TLS stack is not independently reviewed (cancho#209); the README says so.
  4. POST, then MCP (--with fetch), then redirects.

No test touches the Internet. Loopback servers and a CA made for the tests, mutation testing over the request builder, the header allow-list, the redirect logic and the peer check.
